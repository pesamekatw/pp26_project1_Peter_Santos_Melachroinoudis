Στην παρούσα εργασία καλείστε να υλοποιήσετε ένα mini σχήμα βάσης δεδομένων για τη
γραμματεία του τμήματος, χρησιμοποιώντας γλώσσα C και το POSIX API. Συγκεκριμένα
θέλουμε να κρατάμε στοιχεία για:
Φοιτητές (ΑΜ, όνομα, επμο, έτοςΦοίτησης)
Μαθήματα (ΚωδικοςΜαθήματος, Τίτλος, Εξάμηνο, Περιγραφή)
Βαθμολογίες (ΑΜ, ΚωδικόςΜαθήματος, βαθμός)


Τα στοιχεία αυτά σώζονται σε τρία αντίστοιχα αρχεία.
Το σύστημα ακολουθεί την αρχιτεκτονική client server. Στη μεριά του client εμφανίζεται
μέσω μενού επιλογών η δυνατότητα να εισάγει, ενημερώσει, διαγράψει, στοιχεία για
συγκεκριμένο φοιτητή, μάθημα και βαθμολογία (9 επιλογές). Επιπλέον η δυνατότητα
αναζήτησης όλων των βαθμών ενός φοιτητή και όλων των βαθμολογιών σε ένα μάθημα (11
επιλογές συνολικά).


Ο client κατόπιν της επιλογής του χρήστη αποστέλλει τα στοιχεία του ερωτήματος στον
server που είναι υπεύθυνος για το χειρισμό της βάσης δεδομένων (ο client δεν έχει
απευθείας πρόσβαση στα αρχεία, μόνο ο server έχει). Η επικοινωνία client server γίνεται
μέσω Internetstream sockets σε port της επιλογής σας. Ο client αφού αποστείλει το ερώτημα
κωδικοποιημένο ως εξής <ΙDερωτήματος> <παράμετροι>, λαμβάνει την απάντηση από τον
server και εμφανίζει στην οθόνη το αποτέλεσμα που έλαβε.


Ο server για κάθε client που συνδέεται δημιουργεί νέο process (working process) στο οποίο
περνάει το socket της σύνδεσης και το οποίο είναι υπεύθυνο για να απαντήσει στα
ερωτήματα του client.


Τα ερωτήματα και η επεξεργασία τους γίνονται από ξεχωριστά executables. Τα executables
αυτά χειρίζονται απευθείας τα αρχεία δεδομένων και αναλαμβάνουν να συνθέσουν την
απάντηση η οποία και θα προωθηθεί τελικά στον client. Ένα working process διαβάζει και
αναλύει το ερώτημα που έρχεται. Στη συνέχεια δημιουργεί μία διαδικασία παιδί (query
process) η οποία και θα καλέσει το αντίστοιχο exec που επεξεργάζεται το ερώτημα. Η
αναγκαία επικοινωνία μεταξύ working process και query process γίνεται μέσω pipe και
ανακατεύθυνση εισόδου/εξόδου. To query process τερματίζει όταν τελειώσει το executable.
Αφού το working process λάβει τα αποτελέσματα από το query process τα προωθεί στο
socket που συνδέεται με τον client και αναμένει το επόμενο ερώτημα ή ειδικό κωδικό
τερματισμού στην οποία περίπτωση τερματίζει το working process.


Υλοποιήστε τα executables ως εξής. Κάθε executable θα δέχεται αντίστοιχες παραμέτρους
κατά την κλήση του. Στη συνέχεια θα διαβάζει και θα φορτώνει στη μνήμη τα περιεχόμενα
των αρχείων που χρειάζεται. Για τα ερωτήματα εισαγωγής και ενημέρωσης θα
χρησιμοποιούνται δυναμικοί πίνακες για να σωθούν τα δεδομένα στη μνήμη, για τα
ερωτήματα διαγραφής λίστες. Για τις εμφανίσεις (2 στον αριθμό) ό,τι δομή θέλετε. Τα αρχεία
θα πρέπει να είναι πάντα ταξινομημένα, οι φοιτητές ως προς ΑΜ, τα μαθήματα ως προς τον
κωδικό και για τις βαθμολογίες πρώτα ως προς ΑΜ και μετά ως προς ΚωδικόΜαθήματος.
Φροντίστε ώστε στις αναζητήσεις που θα χρειαστούν να εκμεταλλεύεστε κατά το δυνατόν
το γεγονός ότι τα αρχεία είναι ταξινομημένα. Πιθανώς να σας φανούν χρήσιμοι αναλόγως
του ερωτήματος και οι αλγόριθμοι quicksort, insertionsort. Έξτρα μπόνους για τη χρήση
generic δυναμικών πινάκων και λιστών. Ασχέτως λεπτομερειών υλοποίησης, τα executables
γράφουν τα αντίστοιχα αποτελέσματα στον default file descriptor για έξοδο και παγιώνουν
ότι αλλαγές χρειαστεί να γίνουν στα αρχεία πριν τερματίσουν.


Στα πλαίσια της εργασίας αυτής δε χρειάζεται να ασχοληθείτε με τα ζητήματα συγχρονισμού
που ανακύπτουν.
